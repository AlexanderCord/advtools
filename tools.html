01 — AI systems

Guardrails and agents

AI guardrails for the SDLC

evaluation gates · failure-mode handling · architecture

The structure that lets a team ship AI-assisted work quickly without shipping something wrong. Speed and safety usually get traded against each other because the architecture forces the trade — it does not have to.

evaluation gates in the delivery path, not bolted on after release
explicit failure-mode handling: what the system does when the model is wrong, not only when it is right
review and approval boundaries drawn where a human decision actually changes the outcome
built for time to market — the point is to remove the review bottleneck, not add one

research agents that pull measured demand and SERP composition rather than vendor headline numbers
audit agents that check an AI system against its own stated failure modes

02 — booking platforms

Multi-supplier inventory

Cruise booking engine

multi-supplier · availability · payments

A booking platform aggregating cruise inventory across multiple suppliers into one search, one basket and one confirmation path. It won an industry award for the best booking system in its market.

multi-supplier search, availability and pricing behind a single funnel
supplier failure isolated so one slow or down connection does not take the search with it
the hard part is never the UI — it is reconciling inventory that disagrees
award-winning in its category

Ingestion and deduplication framework

GCP · Cloud SQL · Cloud Run · FastAPI

Reusable pipeline for hotel, cruise and tour/event inventory: ingest from many suppliers, normalise to a canonical entity model, and resolve the same product sold by different vendors into one row. Applied across all three industries.

nightly parser into Cloud SQL, IAM-private API surface
canonical place resolution with attraction-overlap grouping (same / similar)
deduplication is the whole problem: in one corpus of 1,178 entities only 45 were genuinely multi-supplier — a finding that killed the premise the pipeline was built on, which is exactly what you want a pipeline to tell you
test-gated: 35/35 green as a release condition on the search layer, 789 offers across 6 countries

03 — measurement

Attribution, dashboards, integrations

Click-to-outcome attribution harness

GTM · server-side · BigQuery · offline conversions

The stack we use to prove a click became revenue rather than assuming it. Built after our own analytics disagreed with a partner's by an order of magnitude.

gclid captured at landing and carried to the order record, so an offline outcome uploads back weeks later
conversion fires on a confirmed server response, never on form submit — firing on submit counts leads that never arrived
outbound links instrumented as real anchors: a window.open() outbound is popup-blockable, and a blocked one looks identical to a successful one
own-traffic exclusion enforced in the query layer, not left to the reader to remember

Dashboards and metric layers

BigQuery · Looker Studio · Mixpanel

Spend joined to orders joined to margin, refreshed nightly, with the funnel defined once in the warehouse rather than three times in three tools.

one metric definition in the warehouse, consumed by every surface
funnel stages instrumented end to end: impression, click, landing, lead, order, margin
built to be handed over — documented, not a consultant-shaped dependency

Marketing and reporting API integrations

Google Ads · GA4 · Mixpanel · DataForSEO · Semrush · supplier APIs

Connectors across ad platforms, analytics, keyword and SERP vendors, email, and travel supplier APIs — with the per-vendor billing model attached, so a data pull has a known cost before it runs.

ad platform, analytics and attribution APIs on the spend side
keyword, SERP and competitive-intelligence vendors on the research side
travel supplier and affiliate APIs on the inventory side
rate limits, pagination and partial-failure handling treated as requirements rather than surprises

04 — ad operations

Campaign automation

Mutation-capable Google Ads control plane

Google Ads API v24 · Python · MCP

A fork of the read-only Google Ads MCP server with write operations added, wrapped in the safety rails you want when a model can create campaigns.

campaigns created PAUSED by default — nothing can spend without a human enabling it
validate_only dry-run path, and a hard daily-budget ceiling
whole campaign built in a single MutateGoogleAdsRequest with temporary resource names, so a partial failure rolls back instead of leaving orphans
ad text pre-flighted against length limits before any mutate — a violation mid-run leaves a campaign and ad group with no ad in them

Keyword and demand corpus

SQLite · DataForSEO · Semrush

A measured keyword database built to stop us trusting vendor headline numbers.

144,000 keywords across 27 markets
entry bid and achieved CPC held as separate fields — conflating them is how models end up wrong by multiples
brand-term detection and junk-intent patterns enforced in the query layer, not as constants nobody reads
