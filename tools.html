Internal tooling

We build it for ourselves first.

None of this is a product. It is the tooling we built to run our own paid acquisition and data work — and it is the reason an audit takes ten days instead of ten weeks. If you want any of it deployed in your stack, that is a build engagement.

01 — data

Research and inventory

Keyword corpus

SQLite · DataForSEO · Semrush

A measured keyword database built to stop us trusting vendor headline numbers. Every row carries the metric we actually bid on, not the one the tool reports first.

144,000 keywords across 27 markets
entry bid and achieved CPC held as separate fields — conflating them is how models end up wrong by multiples
brand-term detection, junk-intent patterns and market exclusions enforced in the query layer, not as constants nobody reads
per-vendor billing model so a research pass has a known cost before it runs

Cross-supplier inventory pipeline

GCP · Cloud SQL · Cloud Run · FastAPI

Normalises product inventory from three travel suppliers into one canonical entity model, so the same thing sold by different vendors resolves to one row.

nightly Cloud Run parser into Cloud SQL, IAM-private API surface
canonical place resolution with attraction-overlap grouping (same / similar)
Basic-Auth data explorer for browsing offers, entities and geography
the pipeline's most valuable output was a negative: of 1,178 entities, only 45 were genuinely multi-supplier — which killed the premise it was built on

02 — ad operations

Campaign automation

Mutation-capable Google Ads control plane

Google Ads API v24 · Python · MCP

A fork of the read-only Google Ads MCP server with write operations added, wrapped in the safety rails you want when a model can create campaigns.

campaigns created PAUSED by default — nothing can spend without a human enabling it
validate_only dry-run path, and a hard daily-budget ceiling
whole campaign built in a single MutateGoogleAdsRequest with temporary resource names, so a partial failure rolls back instead of leaving orphans
micros computed as exact multiples of the billable unit — float arithmetic here silently produces unbillable bids

Campaign launcher with preflight

Python · Google Ads API

Declarative campaign definitions that fail before they touch the API rather than halfway through it.

ad text checked against headline and description limits before any mutate — a length violation mid-run leaves a campaign and ad group created with no ad in them
negative-keyword lists attached per campaign, because new campaigns do not inherit shared lists
ad rotation set on the ad group, never the campaign — the v24 API accepts the latter and ignores it
per-keyword max CPC, presence-only geo targeting, search network only

03 — measurement

Attribution harness

Click-to-outcome instrumentation

GTM · Mixpanel · BigQuery · offline conversions

The stack we use to prove a click became revenue, rather than assuming it. Built after our own analytics disagreed with a partner's by an order of magnitude.

gclid captured at landing and carried to the subscriber or order record, so an offline outcome can be uploaded back weeks later
conversion fires on a confirmed server response, never on form submit — firing on submit counts leads that never arrived
outbound links instrumented as real anchors: a window.open() outbound is popup-blockable and a blocked one looks identical to a successful one in analytics
own-traffic exclusion enforced in every query, not left to the reader to remember

Search meta-aggregator

Python · FastAPI · LLM extraction

A test-gated pipeline joining multi-supplier offers to cross-site review data, with LLM extraction costed per document before any batch runs.

789 offers across 6 countries, pipeline through BFF to UI
35/35 tests green as a release gate
extraction cost modelled per document up front, so a corpus-wide run has a price before it starts
