01 — scope

Four layers, because attackers do not stop at one

A scanner covers the first layer. The breaches that end companies usually start in the other three.

ARCHITECTURE

How the system is put together

Trust boundaries, authentication and session design, tenant isolation, what the blast radius looks like when any one component is taken.

  • authn / authz model review
  • multi-tenant data separation
  • secrets handling and rotation
  • third-party and supplier surface
CLOUD

What is actually deployed

The configuration in the account, not the one in the diagram. IAM over-permission is the single most common finding we write up.

  • IAM roles and standing privilege
  • network exposure and egress
  • storage, backup and encryption
  • logging that would survive an incident
CODE

The parts that handle value

Targeted review of authentication, payment, booking and admin paths rather than an undifferentiated sweep of the repository.

  • injection and deserialization paths
  • access control at the object level
  • dependency and supply-chain risk
  • cryptography actually in use
PROCESS / SSDLC

How a fix reaches production

The layer nobody audits. A perfect codebase with no review gate regresses within a quarter — so we audit the pipeline that keeps it fixed.

  • branch protection and review gates
  • CI checks, SAST and dependency scanning
  • secrets in history and in build logs
  • who can deploy, and what that requires
